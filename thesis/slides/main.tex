\section{Problem}

\begin{frame}{What is my thesis about?}
    M \ldots Molecular structure \quad
    S \ldots Mass spectrum
    \begin{itemize}
%      \item \textbf{Computational mass spectrometry} with a focus on \textbf{MS spectrum modeling}
        \item Formulated mathematically as a function:
            \[
                f : M \to S
            \]
        \item Investigation of the \textbf{inverse problem}:
            \[
                f^{-1} : S \to M
            \]
        \item Integration of \textbf{chemically studied reaction rules} modeled in \textbf{M\O D}
        \item Use of fragmentation trees to support traditional machine-learning-based MS models
    \end{itemize}
\end{frame}
\note{
    What is this project about?

    I formulate MS modeling mathematically as a function mapping a
    molecular structure to its mass spectrum,

    and I study the inverse problem of mapping a spectrum back to a
    structure.

    The key idea is to bring in the relationships between the fragments,

    which I model in M\O D, and use them to enhance the ML models.
}

\section{Background}

\begin{frame}{Motivation}
    \centering
    \resizebox{0.95\textwidth}{!}{
        \input{../shared/figures/motivation.tikz.tex}
    }
    \vskip 0.6cm
    {\footnotesize Acquisition fast, interpretation slow $\Rightarrow$ the
    bottleneck.}
\end{frame}
\note{
    Why would we want to do MS modeling? What is the motivation?

    Mass spectrometry is one of the most widely used tools for molecular
    analysis, but interpreting MS data is still largely expert-driven and
    time-consuming.

    So the high throughput in data acquisition does not carry through to
    the analysis --- that is the bottleneck.

    And by incorporating chemical structure, we can make the ML models
    more interpretable and help them generalize.
}

    We have a sample, which is ionized;

    the ions are then separated by their mass-to-charge ratio,

    and detected to produce a spectrum.

    Under electron ionization the molecule breaks into fragments, so the
    spectrum is essentially a fingerprint of those fragments --- which is
    exactly what we exploit later.
}

\begin{frame}{M\O D - Predicate}
    \centering
    \resizebox{0.95\textwidth}{!}{
        \input{../shared/figures/predicate-filter.tikz.tex}
    }
\end{frame}
\note{
    In M\O D, predicates act as callbacks during the transformation,

    which I use to filter candidates based on the rule extension.

    In the next slides I will show examples of the predicates I
    implemented for this filtering.
}

\begin{frame}{M\O D - Predicate - Alkyl Group}
    \centering
    \resizebox{0.95\textwidth}{!}{%
        \input{../shared/figures/predicate-alkyl.tikz.tex}
    }
\end{frame}
\note{
    A hydrocarbon (alkyl) substituent contains only C and H atoms.

    Starting from the rule-extension location, I collect neighbors in a
    breadth-first manner until I reach atoms that are already in the match
    of the original rule.

    If every collected atom is a C or H, the group is a valid alkyl group;
    otherwise it is rejected.
}

\begin{frame}{M\O D - Predicate - Heteroatom Group}
    \centering
    \resizebox{0.95\textwidth}{!}{%
        \input{../shared/figures/predicate-heteroatom.tikz.tex}
    }
\end{frame}
\note{
    A valid heteroatom group must contain at least one atom that is not C
    or H.

    Again I collect the neighbors breadth-first, those not matched by the
    original rule,

    and I check whether that set contains anything outside \{H, C\}.

    If it does, the group is a valid heteroatom group; if it is a subset
    of \{H, C\}, it is rejected.
}

\begin{frame}{M\O D - Predicate - Saturation}
    \vspace{1.5em}
    \centering
    \resizebox{\textwidth}{!}{
        \input{../shared/figures/predicate-saturation.tikz.tex}
    }
\end{frame}
\note{
    The saturation predicate checks for a chain of carbon atoms connected
    only by single bonds, where each carbon carries only hydrogen atoms as
    side branches.

    I search from the start atom to the end atom along C--C single bonds:
    the top example is saturated, the bottom one fails because of the
    branching carbon and the double bond.
}

\begin{frame}[fragile]{Architecture Diagram}
    \centering
    \begin{adjustbox}{max totalsize={\textwidth}{0.86\textheight},center}
        \input{../shared/figures/architecture_diagram.tikz.tex}
    \end{adjustbox}

\note{
    This is the architecture of the model I implemented. It has three
    inputs: the molecule graph, the derivation (fragmentation) graph, and
    the mass spectrum.

    Each input is mapped into one shared latent space by its own encoder
    --- a GCN with global pooling for the molecule, a two-level graph
    encoder over the derivation graph for the fragments, and a residual MLP
    for the spectrum.

    In the forward direction the molecular and fragment latents are fused
    and decoded into a predicted spectrum.

    Importantly, the backward direction is not a spectrum-to-graph decoder:
    it is a retrieval path. The spectrum embedding is aligned with the
    molecular embeddings, so at test time I retrieve the nearest candidate
    structures by cosine similarity and then rerank them with the forward
    model.

    The two directions share the task heads and decoder and are tied
    together by auxiliary losses --- cycle-consistency and InfoNCE
    contrastive alignment --- so forward prediction and inverse retrieval
    constrain the same latent space.
}

\section{Results}
\begin{frame}{Results -- Bidirectional Retrieval}
    {\footnotesize Proof-of-concept $\cdot$ ${\sim}100$ EI compounds
    $\cdot$ $22$ test queries}
    \vskip 0.4em
    \begin{columns}[c,onlytextwidth]
      \column{0.4\textwidth}
        \centering
        \begin{tabular}{ l r }
          \hline
          Metric & Full model \\
          \hline
          Recall@1  & $0.091$ \\
          Recall@5  & $0.318$ \\
          Recall@10 & $0.500$ \\
          Recall@20 & $0.864$ \\
          MRR       & $0.243$ \\
          \hline
        \end{tabular}
      \column{0.58\textwidth}
        \centering
        \includesvg[width=\linewidth]{../shared/figures/recall_at_k.svg}
    \end{columns}
    \vskip 0.3em
    \centering
    {\footnotesize $\Rightarrow$ candidate narrowing, not single-shot ID}
\end{frame}
\note{
    Now the results. This is a proof of concept on the order of a hundred
    EI compounds, with 22 held-out test queries.

    Recall at k is the fraction of queries whose true structure is among
    the top-k retrieved candidates.

    For the full model, Recall@1 is about 0.09, Recall@5 about 0.32,
    Recall@10 is 0.50, Recall@20 is 0.86, and the mean reciprocal rank is
    0.24.

    So top-1 identification is limited, but the correct molecule is
    usually pulled into the top of the ranked list. The system behaves as
    a candidate-narrowing tool --- which is still useful in a real
    structure-elucidation workflow --- rather than a single-shot
    identifier.

    Note the small test set: 22 queries means recall moves in steps of
    about 0.045, so I read differences between variants cautiously.
}

\begin{frame}{Results -- What Actually Helps? (Ablation)}
    \centering
    \includesvg[width=0.58\linewidth]{../shared/figures/cosine_mrr.svg}
    \vskip 0.2em
    {\footnotesize
    \begin{itemize}
      \item Forward cosine ${\approx}0.43$ --- flat across ablations
      \item \textbf{Reranking}: only significant gain
            (MRR $0.24 \to 0.10$, $p \approx 0.013$)
      \item Fragment branch: no significant benefit yet
    \end{itemize}}
\end{frame}
\note{
    To see what actually drives performance, I ran an ablation against the
    full model: no fragments, no derivation graph, and no reranking.

    First, the forward task: all variants reach almost the same cosine
    similarity, around 0.43. Forward reconstruction is basically
    insensitive to the ablations.

    Second, the one clearly significant effect is reranking. Removing it
    drops the mean reciprocal rank from 0.24 to 0.10, with a p-value
    around 0.013. So much of the retrieval benefit comes from combining
    latent-space retrieval with forward-model rescoring.

    Third --- and this is the honest part --- the fragment and
    derivation-graph branches do not give a statistically significant gain
    yet. In its current form the fragment representation is largely
    redundant given the molecular encoder.

    So the main contribution here is not a headline performance win from
    fragment augmentation; it is establishing a fragment-augmented
    bidirectional framework whose strengths and failure modes can be
    analysed systematically --- which is exactly what motivates the
    outlook.
}


\section{Conclusions}
\begin{frame}{Conclusions}
    \textbf{Contributions}
    \begin{itemize}
        \item One bidirectional model: M\O D graphs + two-level molecule
              + aligned spectral/structural embeddings
              ($f: M \!\to\! S$, $f^{-1}: S \!\to\! M$)
        \item Rule-extension DSL: alkyl / heteroatom / saturation
        \item Coupled objective: cosine\,+\,Wasserstein $\cdot$ InfoNCE
              $\cdot$ retrieval\,+\,rerank
    \end{itemize}
    \vskip 0.3em
    \textbf{Honest assessment}
    \begin{itemize}
        \item Framework works; reranking helps
        \item Fragment branch: no significant gain yet
        \item Contribution = analysable framework, not accuracy win
    \end{itemize}
\end{frame}
\note{
    To conclude, the contributions: to my knowledge this is the first
    framework to couple M\O D-derived derivation graphs with a two-level
    molecular representation and to align spectral and structural
    embeddings in a single bidirectional model, covering both the forward
    and the inverse direction. Along the way I built a rule-extension DSL
    with the chemical predicates I showed, and a coupled forward--backward
    training objective.

    And the honest assessment: the framework is functional and reranking
    clearly helps, but the fragment branch does not yet give a significant
    gain over the molecular encoder alone. So the value of this work is a
    bidirectional framework whose behaviour and failure modes I can analyse
    systematically --- which sets up the outlook.
}

\begin{frame}{Outlook -- Learn to \emph{Generate} Fragmentation}
    Model \emph{encodes} precomputed M\O D graphs --- it does \emph{not}
    learn fragmentation.
    \vskip 0.5em
    Inspiration: \textbf{ICEBERG} \cite{Goldman2024} ---
    \emph{Generate}\,--\,\emph{Score}.
    \begin{itemize}
        \item Have: the \textbf{Score} side
        \item Missing: a \textbf{Generate} module (which fragmentations?)
        \item M\O D graphs $\rightarrow$ proxy supervision
    \end{itemize}
    \vskip 0.5em
    {\footnotesize prune/rank $\to$ autoregressive expansion $\to$ joint
    end-to-end}
\end{frame}
\note{
    The clearest boundary of the current approach is that it does not learn
    fragmentation itself: it encodes derivation graphs that the rule-based
    M\O D pipeline computes upstream. The learning problem only begins
    after the fragmentation space has been built.

    The natural next step, and my main direction for future work, is to
    move from encoding fragmentation to generating it. The key inspiration
    is ICEBERG, by Goldman and colleagues, which splits the task into a
    Generate module that proposes likely fragmentation events and a Score
    module that assigns intensities.

    Seen this way, my model already supplies the Score side: it embeds
    molecules, fragments, and spectra into a shared space, predicts
    spectra, and aligns and retrieves. What is missing is the upstream
    Generate module that decides which fragments enter at all --- and the
    symbolic M\O D derivation graphs could serve as proxy supervision for
    training it.

    I see a staged path: first learn to prune or rank derivation steps,
    then learn to expand fragmentation graphs autoregressively, and finally
    couple generation and scoring into one end-to-end model.
}

\begin{frame}{Outlook -- Toward a Generate--Score Architecture}
    \centering
    \begin{adjustbox}{max totalsize={\textwidth}{0.86\textheight},center}
        \input{../shared/figures/generative-future.tikz.tex}
    \end{adjustbox}
\end{frame}
\note{
    This figure sketches that target architecture. A learned Generate
    module, trained with the M\O D derivation graphs as proxy labels,
    proposes the fragmentation structure; the Score module --- essentially
    my present model --- embeds molecule, fragments, and spectrum in a
    shared latent space and produces both the forward spectrum prediction
    and the inverse retrieval. The two are trained end-to-end, so the model
    learns not only how to use fragments but which fragmentation structures
    to construct in the first place.
}
